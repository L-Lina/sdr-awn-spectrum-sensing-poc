# NDSS 研究提案（繁體中文）

## 提案名稱

**SentryAMC：面向端到端射頻監測管線的自適應對抗攻擊、可信防禦與實體世界驗證**

英文暫定題名：

> SentryAMC: Adaptive Adversarial Attacks and Trustworthy Defenses for End-to-End RF Monitoring Pipelines

## 一、研究摘要

自動調變分類（Automatic Modulation Classification, AMC）已逐漸被納入認知無線電、頻譜監測、干擾分析與安全營運流程。然而，既有研究多半把 AMC 視為獨立分類器，只在已切割且對齊的固定長度 IQ 樣本上評估對抗攻擊。真實監測流程則包含能量偵測、事件分段、視窗選擇、正規化、分類器、頻域防禦、信心判斷與事件彙整。攻擊者不必只攻擊神經網路，也可以操控偵測門檻、事件邊界、最大能量視窗或防禦路由器，使系統漏報、誤報、錯誤分類或長期處於不確定狀態。

本研究擬建立一套可重現的端到端射頻安全評估框架，以「預先通道化之複數基頻串流上的能量觸發 AMC」為近期系統邊界，研究防禦感知的自適應攻擊如何影響完整監測管線，並提出保留證據、允許棄權及失效關閉（fail-closed）的可信防禦設計。研究將從離線 RadioML 與 `.cfile` 重播開始，逐步進展至纜線重播、獨立擾動注入與屏蔽環境 OTA 測試。

本提案不預設目前系統已具備寬頻頻譜感知、通訊解碼或自主控制能力。現有程式庫是離線實驗平台；本研究的核心工作之一，就是將其擴充為可被嚴格攻擊、量測與驗證的安全監測原型。

## 二、研究背景與問題陳述

AMC 模型常在乾淨資料集上取得良好準確率，但其部署環境與傳統影像分類不同：

1. 輸入是連續 IQ 串流，而非天然切割好的樣本。
2. 訊號是否存在、事件起訖位置及選取哪一段樣本，皆由前端演算法決定。
3. 通道、頻率偏移、增益、量化、同步誤差及硬體非理想性會改變攻擊效果。
4. 錯誤結果可能造成監測事件被漏報、分析資源遭大量誤報耗盡，或下游決策依據被污染。
5. 確定性的頻域前處理並非祕密；在白箱威脅模型中，攻擊者可直接針對完整防禦最佳化。

目前大量防禦研究只對未防禦分類器產生攻擊，再把相同樣本送入防禦模組。這類實驗只能稱為「防禦未知」或「oblivious」評估，不能證明完整防禦管線具有白箱強健性。因此，本研究要回答的核心問題不是「Top-K 是否能恢復某些既有對抗樣本」，而是：

> 當攻擊者知道偵測器、分段器、前處理、防禦路由與分類模型時，是否能以具物理意義的有限擾動，可靠地破壞端到端射頻監測結果？系統又應如何在無法保證正確分類時安全地退化？

### 2.1 實際頻譜感知威脅模型

本提案採用「附近攻擊者以獨立 SDR 發射加性 RF 波形」作為主要實際威脅。攻擊者可以選擇頻率、頻寬、功率、波形、發射時間及 duty cycle，並知道能量偵測、事件分段、視窗選擇、AMC 與防禦設計；但不能直接覆寫接收端 IQ tensor、修改模型或入侵監測主機，也不假設能與合法發射器精確相位同步。

主要攻擊面包括噪聲底污染、假佔用洪泛、事件橋接、邊界延伸、最大能量視窗劫持，以及針對完整防禦管線的 AMC 誤分類或棄權 DoS。數位 tensor 注入只作為演算法安全上界；實體可行性結論必須經獨立 SDR 的纜線或屏蔽 OTA 實驗驗證。

完整的訊號模型、攻擊者分層、信任邊界、八類攻擊目標、安全需求、實驗矩陣與評估指標，見 [`PRACTICAL_SPECTRUM_SENSING_THREAT_MODEL_ZH_TW.md`](PRACTICAL_SPECTRUM_SENSING_THREAT_MODEL_ZH_TW.md)。

## 三、研究目標

本研究有四項主要目標：

### 目標一：建立端到端且可重現的威脅模型

明確定義攻擊者的知識、能力、目標與限制，涵蓋：

- 白箱、灰箱與黑箱知識條件。
- 數位樣本注入、纜線 RF 注入及受控 OTA 傳輸。
- 擾動功率、頻寬、時間長度、因果性與通道限制。
- 漏偵測、事件分裂／合併、錯誤分類、目標分類、信心壓低及誤報洪泛等攻擊目標。
- 攻擊者是否可觀察系統回應，以及可用的查詢次數。

### 目標二：建構針對完整管線的自適應攻擊

攻擊目標將包含完整流程，而非只有 AWN 分類器：

```text
IQ 串流
  -> 能量偵測
  -> 區域擷取與合併
  -> 視窗選擇
  -> AWN 前處理
  -> AMC 模型
  -> Top-K／路由防禦
  -> 事件層彙整與棄權策略
```

預計實作並比較：

- 以可微分代理模型近似門檻、Top-K 與離散路由。
- BPDA／straight-through estimator。
- 當防禦含隨機性時使用 EOT。
- Square Attack、SPSA 或 NES 等梯度無關攻擊。
- 多次隨機重啟與不同初始化。
- 同時攻擊事件偵測、視窗選擇及最終分類的聯合目標函數。

### 目標三：設計可安全退化的可信監測機制

本研究不把「強制輸出一個分類標籤」視為唯一成功條件。系統將支援：

- 真實模型載入失敗時停止正式推論，而非回傳隨機 logits。
- 對低信心、高熵、模型／防禦不一致及異常事件採取棄權。
- 保存每個偵測事件與原始證據，避免防禦模組直接刪除可疑事件。
- 使用多個重疊視窗進行事件層彙整，而非只依賴單一最大能量視窗。
- 將防禦啟動視為安全訊號之一，交由分析流程升級處理。

### 目標四：驗證數位攻擊是否能跨越實體通道

建立由低成本、可重現到高真實度的驗證階梯：

1. RadioML 離線資料。
2. 已知內容的 `complex64` `.cfile` 重播。
3. SDR 纜線乾淨訊號重播。
4. 訊號與擾動經不同來源合成後的纜線注入。
5. 獨立攻擊發射器的受控加性注入。
6. 屏蔽環境中的 OTA 實驗。
7. 僅提供建議、不自動採取動作的影子部署。

## 四、研究問題

本研究將回答下列研究問題（Research Questions, RQ）：

- **RQ1：** 防禦未知攻擊所呈現的恢復率，在防禦感知的自適應攻擊下會下降多少？
- **RQ2：** 攻擊完整前端管線，是否比只攻擊 AMC 分類器更容易造成漏報、誤報或事件邊界錯誤？
- **RQ3：** 最大能量視窗、Top-K 頻域保留與動態路由分別引入哪些新的攻擊面？
- **RQ4：** 重疊視窗、事件層彙整、棄權與證據保留能否降低安全風險，而不造成不可接受的誤報率與延遲？
- **RQ5：** 數位域中成功的擾動，在頻率偏移、通道雜訊、增益誤差、量化及非同步條件下能保留多少攻擊效果？
- **RQ6：** 哪些可量測條件能預測攻擊從離線樣本轉移至纜線或 OTA 環境的成功率？

## 五、系統設計與實作計畫

### 5.1 第一階段：正式 `.cfile` 輸入與失效關閉

將既有 `src/sensing/iq_source.py` 的 `.cfile` 載入功能接入正式實驗路徑：

```text
experiments/run_full_experiment.py
  -> src/utils/pipeline.py
  -> src/adapters/awn_adapter.py
```

每次擷取須記錄：

- 樣本率、中心頻率、增益與時間戳。
- IQ dtype、位元序、通道數與縮放方式。
- NaN／Inf、削波率、平均功率與峰均比。
- 模型 checkpoint、程式版本、隨機種子與完整設定。
- 實際使用的 AWN、攻擊與防禦 backend。

正式模式必須要求真實模型成功載入；dummy backend 只能在明確標示的 dry-run 中使用。

### 5.2 第二階段：串流化事件處理

把離線處理重構為可維持狀態的元件：

- `IQSource`
- `CaptureHealthMonitor`
- `ActivityDetector`
- `EventTracker`
- `WindowExtractor`
- `AWNRuntime`
- `DefenseRuntime`
- `DecisionPolicy`
- `EventSink`

能量偵測器將加入因果式噪聲估計、遲滯、跨 chunk 事件狀態及最低持續時間。測試需證明同一段 IQ 以整檔或不同 chunk 大小處理時，在允許的邊界誤差內產生一致結果。

### 5.3 第三階段：事件層可信決策

每個事件使用多個重疊視窗，記錄：

- 每個視窗的類別機率、熵與信心。
- 原始模型與防禦模型的預測差異。
- 視窗間的一致性。
- 防禦是否啟動及其參數。
- 最終標籤、棄權原因與事件證據位置。

事件策略的輸出限定為「分類」、「不確定／需人工分析」或「輸入／模型故障」，不直接控制頻譜資源。

### 5.4 第四階段：寬頻延伸（選配）

若論文要使用「寬頻頻譜感知」一詞，必須新增 STFT 或 polyphase channelizer，並評估同時多訊號、鄰道洩漏、不同頻寬與動態佔用。若無法完成，論文將維持「預先通道化串流上的能量觸發 AMC」之精確描述。

## 六、實驗方法

### 6.1 資料與模型

至少使用：

- RadioML 2016.10A 作為可與既有研究比較的基準。
- 一組可公開或可合法釋出的 SDR 擷取資料。
- AWN，以及至少一個不同架構的 AMC 模型，以避免結論只適用單一模型。

資料切分必須以唯一設定檔固定，明確記錄訓練、驗證與測試樣本數，避免同一 `(modulation, SNR)` cell 在不同章節出現矛盾數量。

### 6.2 攻擊設定

每個攻擊報告：

- 威脅模型及攻擊者知識。
- 擾動範數與功率限制。
- 迭代次數、步長、重啟次數及停止條件。
- 查詢次數與計算成本。
- 是否針對完整防禦最佳化。
- 數位、通道模擬、纜線或 OTA 條件。

CW、FGSM、PGD 與其他攻擊參數由單一機器可讀設定產生，論文表格不得另行手動維護一份不一致的數值。

### 6.3 基準方法

比較對象包括：

- 無防禦 AMC。
- 固定 K 的 Top-K 頻域前處理。
- 動態／Adaptive-K。
- 對抗訓練。
- 輸入去噪或頻域濾波基準。
- 只使用信心閾值的棄權基準。
- 多視窗事件彙整與可信決策方法。

所有防禦同時接受 oblivious 與 adaptive 攻擊；主要安全結論以 adaptive 結果為準。

### 6.4 評估指標

**分類與安全：**

- 乾淨準確率與平衡準確率。
- 非目標／目標攻擊成功率。
- 強健準確率。
- 攻擊後棄權率及錯誤接受率。

**感知與事件：**

- 偵測率、漏偵測率與每時間單位誤報數。
- 事件分裂、事件合併與邊界誤差。
- 事件層分類正確率。
- 不確定事件的召回率與分析負載。

**RF 物理量：**

- 擾動對訊號功率比（PSR）。
- EVM、BER（具備可解調訊號時）、頻譜遮罩與佔用頻寬。
- CFO、相位偏移、時間偏移、多徑及增益誤差下的成功率。

**系統：**

- 每階段延遲、端到端延遲與吞吐量。
- 記憶體與 GPU／CPU 使用量。
- dropped samples、backpressure 與模型失效事件。

### 6.5 統計設計

- 使用至少五個獨立隨機種子。
- 報告平均值、標準差及 95% 信賴區間。
- 對主要比較進行適當的配對檢定與多重比較修正。
- 公開樣本索引、設定檔、程式版本與產生表格的腳本。
- 將失敗實驗、無效樣本及排除條件寫入 artifact，而非事後人工刪除。

## 七、預期貢獻

若研究假設獲得實驗支持，預期貢獻為：

1. **端到端 RF 監測威脅模型：** 系統性描述偵測、分段、視窗選擇、分類與防禦之間的聯合攻擊面。
2. **防禦感知攻擊套件：** 提供可重現的 BPDA、代理梯度、EOT 與梯度無關攻擊，避免以 oblivious 攻擊誤判安全性。
3. **可信事件處理架構：** 透過失效關閉、多視窗彙整、棄權與證據保留，使系統在不確定時安全退化。
4. **實體轉移研究：** 量化數位攻擊經通道、硬體與同步誤差後的有效性，建立可重現的纜線／屏蔽 OTA 方法。
5. **可重現 artifact：** 釋出設定、攻擊、事件紀錄格式、分析腳本與不含受限資料的最小測試集。

以上是預期貢獻，不應在實驗完成前寫成已證明的結論。

## 八、風險與替代方案

### 風險一：Adaptive-K 在自適應攻擊下無法提供強健性

這仍是有價值的安全結果。論文可轉向分析「為何防禦未知評估造成錯誤安全感」，並以端到端攻擊面與可信棄權機制為主要貢獻。

### 風險二：數位攻擊無法轉移到 OTA

研究將報告轉移失敗的條件與原因，分析同步、通道與硬體誤差如何破壞攻擊，並避免宣稱實體可行性。纜線注入仍可作為較可控且可重現的中間結果。

### 風險三：無法建立真實自主控制平面

不以虛構控制系統支撐安全影響。近期情境維持被動監測與分析分流，安全後果以漏報、誤報洪泛、事件污染及分析資源耗盡量測。若未實作下游控制，不宣稱已造成自主頻譜配置失效。

### 風險四：資料或硬體無法公開

公開所有可公開的程式、設定、合成測試資料與資料格式，並提供受限資料的雜湊、取得流程及可替代公開資料集。

## 十、Go／No-Go 判準

在將成果定位為 NDSS 完整論文前，至少滿足：

- 已實作針對完整防禦的自適應攻擊，而非只重播舊攻擊。
- 所有論文章節使用一致的資料切分與攻擊參數。
- 至少兩個模型、五個種子及一組 SDR 擷取或受控實體測試。
- 能清楚量測一項安全後果，例如漏報、誤報洪泛或分析資源耗盡。
- 能說明防禦在強自適應攻擊下仍提供何種可重現效益，或提出具有新穎性的負面結果與安全設計原則。
- artifact 可由全新環境產生主要表格，且 backend、版本與失敗案例均可追溯。

若無法滿足自適應攻擊、實體驗證或安全後果三項核心條件，應考慮先投稿通訊、無線安全 workshop 或系統展示類型場域，避免以不足的證據支撐 NDSS 強健性主張。

## 十一、倫理與負責任揭露

本研究僅在自有設備、纜線連接、屏蔽箱或取得明確授權的頻段與環境中進行。OTA 實驗遵守當地法規、發射功率限制及實驗場所規範，不對公共通訊服務發送干擾。公開 artifact 應限制可直接用於未授權干擾的操作細節，同時保留足以驗證科學結論的程式、參數與資料處理流程。
