# 能量觸發自動調變分類系統：現況與元件狀態

## 一、報告目的

本文件記錄一套能量觸發自動調變分類（Automatic Modulation Classification, AMC）系統目前的實作範圍與驗證程度，內容依實際程式與已執行的實驗結果整理，用途有三：一是清楚劃定系統目前能回答哪些問題、不能回答哪些問題；二是把偵測、分類、攻擊與防禦各元件的角色與信任邊界說明清楚；三是逐一標記每個元件屬於已實作、已驗證、僅在數位環境驗證，或尚未實體驗證，避免規劃中的功能被誤讀成已完成的能力。

## 二、研究問題與實際應用

被動式射頻監測是許多頻譜管理與異常偵測場景的共同需求：在授權範圍內持續監聽特定通道，判斷是否有活動、活動屬於哪一種調變，並保留足以事後查證的證據。這類系統的實用價值不在於取代解調或解碼，而在於用相對低成本的方式先做初步分流——一段訊號值得分析人員進一步檢視，還是可以歸類為已知背景活動。

這個應用情境對系統提出幾個具體要求：輸入是連續的 IQ 串流而非天然切割好的樣本；訊號是否存在、事件從哪裡開始與結束、要取哪一段樣本送進分類器，全部由前端演算法決定，而不是由資料集的標註決定；分類結果的可信度必須可以被檢驗，而不是只看模型輸出的信心分數；系統在無法確定的情況下應該傾向於保留證據並提出警示，而不是勉強給出一個可能錯誤的標籤。這些要求決定了系統的元件劃分方式，也決定了後面威脅模型要涵蓋的攻擊面不能只限於分類器本身。

## 三、系統與威脅模型

### 3.1 系統情境

系統設想的部署方式是一個接收授權範圍內特定通道的 SDR 監測節點：持續觀察該通道的能量變化，在偵測到活動時建立事件、擷取樣本、交由 AMC 判斷可能的調變類型，並將標籤、信心與原始 IQ 一併保存供後續查閱。系統本身不發射訊號、不自動封鎖或重新配置頻譜資源，近期的安全後果因此不是自主控制被接管，而是監測結果本身是否可信、監測資源是否可能被低成本耗盡。

### 3.2 Spectrum Sensing 的角色

Spectrum sensing 位於原始 IQ 與 AMC 之間，負責回答「這段時間有沒有活動」「活動從哪裡開始到哪裡結束」「要把哪一段樣本交給分類器」。沒有這一層，系統就只能用固定切割的方式處理連續 IQ，把大量純噪聲片段也送進分類器，既浪費運算資源，也無法建立有意義的事件時間軸。這個角色的重要性在於，它的判斷品質直接決定 AMC 拿到的輸入是不是真的對應到一段真實訊號——如果偵測、合併或視窗選擇被操控，AMC 本身再準確也沒有意義。

### 3.3 保護目標

系統要保護的不是傳輸內容的機密性，而是監測結果本身的完整性與可用性：通道在特定時間是否真的有活動的判斷要正確；事件的起訖時間、是否被錯誤合併或切割要可信；AMC 給出的類別與信心要能反映實際接收到的波形；監測服務不能被以低成本手段長時間阻塞或耗盡分析資源；保存下來的原始 IQ 與相關設定要可追溯、不能被悄悄修改；模型或後端載入失敗、輸出異常值等失效狀況必須明確顯示，不能偽裝成正常的分類結果。

### 3.4 信任邊界

系統假設監測節點的主機、儲存、偵測與分類程式碼、模型檔案本身由維運方控制。不可信的部分是天線接收到的所有射頻能量，以及外部提供、未經驗證的 IQ 擷取檔——包括其中可能缺漏或錯誤的取樣率、中心頻率、增益等資訊。模型輸出的高信心分數也不能直接當作輸入未受干擾的證明。至於主機本身被入侵、模型檔案被置換等供應鏈層級的問題，性質上屬於另一組安全需求，不與本文件討論的射頻層攻擊面混在一起處理。

### 3.5 A0／A1／A2 攻擊者分層

系統的攻擊者能力分成三層，避免用單一模糊的「攻擊者」概念涵蓋差異很大的情境。**A0** 可以直接修改離線 IQ tensor、掌握完整模型與前處理，不受射頻通道限制，主要用途是作為演算法層面的數位白箱基準與除錯手段，其結果不能單獨支持「這個攻擊在實體通道上也成立」的結論。**A1** 是在監測範圍內以獨立商用 SDR 發射加性波形的攻擊者，能選擇頻率、頻寬、功率、波形與發射時間，也了解系統設計，但無法修改接收端主機或模型，也不假設能與合法發射器精確同步——這是目前設定中最貼近實際威脅的攻擊者。**A2** 則是資訊更受限的查詢式攻擊者，只能透過有限的外部回饋（例如可觀察的告警）推測系統反應，受查詢次數與發射資源限制。三層之間是能力與知識條件的差異，不是強度單調遞增的關係。

### 3.6 G1–G8 攻擊目標

在上述攻擊者模型下，系統的攻擊面涵蓋八類具體目標：噪聲底污染，讓門檻被墊高、使弱訊號無法形成事件；假佔用洪泛，用大量短促發射耗盡推論與分析資源；事件橋接，讓原本應分開的兩段活動被錯誤合併；邊界延伸，讓事件起訖被推移，使擷取視窗涵蓋不到完整的合法訊號；最大能量視窗劫持，插入短而強的訊號讓視窗選擇機制改選到攻擊波形；針對 AMC 本身的誤分類或目標分類；針對防禦路由決策的操控，讓系統選錯 K 值或防禦分支；以及證據污染，讓保存下來的事件內容混雜多個來源或錯誤的中繼資料，增加事後追查的難度。這八類目標的共同重點是把攻擊面延伸到偵測、分段與視窗選擇，而不是只把分類器當成唯一的攻擊入口。

## 四、目前系統資料流程

目前正式路徑的資料流程是：

```
IQ 來源（合成串流、RadioML 樣本嵌入、或 .cfile 讀取）
  → 時間能量偵測（噪聲底估計、門檻判斷）
  → occupied-region 擷取、合併與最短長度過濾
  → 視窗選擇（naive 或 max-energy）
  → AWN 前處理與 [N, 2, 128] 格式轉換
  → AWN clean inference
  → 對抗攻擊（可選）
  → Top-K 頻域防禦（可選）
  → AWN attacked／defended inference
  → 逐 segment 結果、感測指標與圖表輸出
```

三種 IQ 來源在這個流程裡是互斥的分支：合成串流與 RadioML 樣本嵌入用於有已知真值位置的實驗（可計算偵測率、邊界誤差等指標），`.cfile` 讀取用於外部提供的原始檔案（沒有真值可用，相關欄位會明確標示為不可用而不是猜測填入）。三個分支共用同一組偵測、分段、前處理與推論程式碼，差異只在輸入來源本身。

## 五、各元件角色與完成狀態

以下每個元件標記其狀態為「已實作且已驗證」、「已實作，僅在 A0 數位環境驗證」、「已接入但尚未實體驗證」或「未實作」，並簡述依據。

### 5.1 Spectrum Sensing

時間能量偵測（滑動視窗功率平滑、中位數噪聲底估計、門檻判斷）、occupied-region 擷取、鄰近區域合併、最短長度過濾，以及 `naive`／`max-energy` 兩種視窗選擇策略，皆已實作並接入正式流程，也已透過 Direct／No-sensing／Sensing／Oracle 四路對照實驗與獨立的 spectrum sensing utility 正式實驗驗證——後者確認了在有無真值資訊介入下，sensing 前端對最終分類準確率的實際影響方向與幅度。狀態：**已實作且已驗證**，但僅限單一預先通道化通道上的時間域偵測，見第七節的系統界線說明。

現行實作可表示為：對輸入 IQ 序列 \(y[n]\)，先計算瞬時功率

\[
p[n] = |y[n]|^2,
\]

再以長度 \(W\)（`window` 參數）的均勻窗做滑動平均，得到平滑功率

\[
\bar{p}[n] = \frac{1}{W}\sum_{i \in \mathcal{W}_n} p[i],
\]

以整段序列平滑功率的中位數作為噪聲底估計

\[
\hat{N} = \operatorname{median}_n(\bar{p}[n]),
\]

門檻為噪聲底估計乘以 `threshold_factor`（記為 \(\alpha\)）

\[
\gamma = \alpha \hat{N},
\]

再以門檻判斷每個樣本是否為佔用狀態，得到占用遮罩

\[
m[n] = \mathbb{1}[\bar{p}[n] > \gamma]。
\]

遮罩經連續區段擷取、依 `merge_gap` 合併相鄰區段、依 `min_region_len` 過濾過短區段後，得到最終的 occupied region 清單。`max-energy` 視窗選擇策略在每個 occupied region 內，以步長 `hop` 滑動一個長度 \(T\)（固定為 128）的候選視窗，計算各候選視窗的平均功率

\[
\bar{p}_{\text{cand}} = \frac{1}{T}\sum_{i \in \text{cand}} |y[i]|^2,
\]

選擇平均功率最高的候選視窗作為該區域的最終分段。整個計算過程只使用滑動平均功率、中位數噪聲底、固定門檻係數與視窗內平均功率，不使用真實訊號的起訖位置或任何標註資訊。

### 5.2 RadioML／synthetic source

RadioML 2016.10a 樣本讀取與嵌入合成噪聲串流的功能已實作，並提供已知的真值起訖位置，供上述四路實驗與 sensing 正式實驗使用。狀態：**已實作且已驗證**。

### 5.3 cfile input

`.cfile` 格式的正式讀取模組支援 complex64、interleaved float32、interleaved int16 三種格式，並已接入正式流程，串接真實 AWN 推論、對抗攻擊與 Top-K 防禦——不經過任何以隨機數值產生分類結果的替代路徑。三種格式對同一組資料的一致性、格式讀取的邊界條件（檔案不存在、內容過短、數值溢位等）皆已測試。狀態：**已接入正式流程並通過格式與功能驗證，尚未完成真實 SDR 擷取檔案之外部驗證**——目前的驗證對象是內部產生的等價測試檔案，實際 SDR 硬體擷取的檔案在取樣率、增益、量化與雜訊特性上是否與測試檔案一致，尚未經過檢驗。

### 5.4 AWN AMC

AWN 模型的載入、真實 checkpoint 推論、`[N, 2, 128]` 輸入格式轉換，皆已實作並在所有正式實驗中使用；模型載入失敗時會明確回報後端狀態，而不是默默改用其他數值來源。狀態：**已實作且已驗證**。模型輸出信心是否可作為輸入未受干擾的判斷依據，以及低信心情況下的棄權機制，目前**未實作**。

### 5.5 Attack adapter

對抗攻擊介面串接真實的 torchattacks 後端，涵蓋十七種攻擊方法，其中 DIFGSM 因 torchattacks 原生實作的 input diversity 機制是針對影像的四維張量設計、無法直接相容於 IQ 序列的張量形狀，改為 **IQ-compatible DIFGSM 自行實作**。這個自行實作的版本已完成以下項目的驗證：輸出張量形狀（shape）、I／Q 兩通道處理的一致性（channel consistency）、梯度計算正確性（gradient）、固定種子下的決定性輸出（deterministic seed）、擾動量符合 Linf 預算的邊界檢查（Linf constraint）、diversity 機制關閉時與無 diversity 版本行為一致（no-diversity equivalence），以及納入十七種攻擊相容性 smoke test 與模型狀態恢復（model state restoration）的正式測試。以上驗證確認這個自行實作版本在測試涵蓋的行為上正確，但**未對 torchattacks 原始影像版本 DIFGSM 的所有行為提出正式等價證明（equivalence proof）**，兩者不應被視為在所有情境下等價。每次攻擊後模型會被確認恢復為 eval 模式，並以重新執行一次乾淨推論的方式驗證模型狀態沒有殘留副作用。狀態：**已實作，僅在 A0 數位環境驗證**——本文件記錄的所有攻擊實驗都是攻擊者直接修改送入分類器的張量，尚未涉及任何射頻層面的驗證，也尚未把偵測、分段與視窗選擇本身納入攻擊目標。

### 5.6 Top-K defense

固定 K 值的頻域前處理防禦已實作並接入正式流程，可與真實 AWN 推論串接使用。功能狀態與防禦效果須分開陳述：**功能狀態為已實作且通過執行驗證**，獨立測試確認防禦模組能正確載入、正確處理輸入並回傳預期形狀的輸出。**防禦效果已透過既有 Phase 4 正式實驗完成 Attack → Top-K → Defended inference 的離線評估**，涵蓋多組 K 值、攻擊方法與調變類型的組合，記錄了受攻擊後準確率、防禦後準確率與是否由防禦恢復正確分類等結果。這組結果具有 condition-dependent 性質——防禦恢復的效果隨 K 值、攻擊方法與調變類型而不同，並非在所有組合下一致有效，**尚未證明固定 K 為跨攻擊、跨調變類型的穩定通用防禦**，也**尚未完成把偵測、分段、防禦與分類一併納入攻擊目標的 full-pipeline defense-aware adaptive attack**。**第六節記錄的低擾動攻擊實驗（FGSM 與五種攻擊）沒有啟用 Top-K**，因此該實驗本身不產生新的「攻擊加防禦」對抗數字，這與既有 Phase 4 已完成的離線評估是兩組不同範圍的結果，不應混為一談。動態選擇 K 值或防禦分支的路由機制**未實作**。

### 5.7 Logging／metrics／latency

每筆結果會記錄感測指標（是否偵測到活動、偵測區間、擷取涵蓋率）、分類結果（乾淨與受攻擊後的預測與信心）、擾動量、各處理階段的耗時，以及行程的峰值記憶體用量。狀態：**已實作且已驗證**。跨多次執行的長期趨勢、事件層級的佇列與延遲統計，以及即時告警機制，**未實作**。

## 六、已完成的正式驗證

以下項目已在正式流程下、以真實 AWN checkpoint 與真實攻擊／防禦後端執行完成：Direct／No-sensing／Sensing／Oracle 四路對照實驗；spectrum sensing utility 正式實驗；十七種攻擊的相容性驗證；核心流程參數（資料集篩選、批次大小、視窗長度邊界等）的驗收；三種格式 cfile 讀取器的一致性測試，以及 cfile 串接真實推論、攻擊與防禦的驗證；攻擊後模型狀態恢復與乾淨推論可重現性的驗證；FGSM 正式基準實驗；PGD、CW、DeepFool、EAD、FAB 五種攻擊的數位基準實驗。以上驗證涵蓋的樣本數、參數設定與執行結果詳見對應結果目錄，逐項數字不在本文件重複列出。

## 七、目前系統界線

目前系統的精確描述是：**預先通道化複數基頻串流上的能量觸發自動調變分類系統**。這句話同時界定了能力範圍：系統處理的是已經由上游選定的單一通道，在時間軸上判斷是否有能量活動，再把偵測到的片段交給分類器；它不涉及頻域上判斷寬頻輸入中哪些頻率子通道被佔用，因為目前沒有實作 channelizer，不能宣稱已完成寬頻頻譜感測。系統的分類輸出僅止於調變類型的判斷，不包含解調、解碼、CRC 驗證或協定解析，因此不能回答訊號內容是什麼、來自哪一台設備。Spectrum sensing 負責活動偵測、事件形成與視窗選擇；AWN 負責調變分類；Top-K 是分類前的頻域前處理，不是 channelizer 也不是頻譜感測元件；對抗攻擊模組目前主要作用於已經擷取好的 AMC 輸入片段，還沒有把偵測與分段本身納入攻擊面。

## 八、目前證據支持的結論

現有結果可以支持以下敘述：偵測、分段、視窗選擇與 AMC 分類已串成單一可重現的正式流程，並在四路對照與 sensing utility 實驗中驗證了 sensing 前端對分類結果的實際影響；`.cfile` 三種常見格式的讀取與正式推論串接已透過內部產生的等價測試檔驗證正確；十七種對抗攻擊在數位環境下皆可正常執行，攻擊後模型狀態可正確恢復；FGSM 與五種低擾動攻擊已建立涵蓋十一種調變、三個訊噪比的正式數位基準，執行過程沒有錯誤、沒有靜默使用替代數值、沒有數值異常；既有 Phase 4 正式實驗已完成固定 K 值 Top-K 防禦在 Attack → Top-K → Defended inference 流程下的離線評估，結果顯示防禦效果隨 K 值、攻擊方法與調變類型而變化。

## 九、尚未驗證的範圍

目前尚未有證據支持以下敘述：系統具備寬頻頻譜感測能力；`.cfile` 讀取器已用實際 SDR 擷取的檔案驗證過外部有效性；任何一種數位攻擊已驗證能在實體射頻通道上成功；攻擊已針對噪聲底估計、事件形成或最大能量視窗選擇本身進行過正式測試；固定 K 值 Top-K 防禦已被證明是跨攻擊、跨調變類型的穩定通用防禦；系統已完成把偵測、分段、防禦與分類一併納入攻擊目標的 full-pipeline defense-aware adaptive attack 評估。A0 數位環境下的攻擊結果只能作為演算法層級的參考，不能直接推論到 A1 等級的實體攻擊者是否能達到相同效果。

## 十、技術缺口與下一步

距離涵蓋完整威脅模型的系統，目前主要缺口包括：即時串流接收與跨處理批次的偵測器狀態保存；抗污染的自適應噪聲底估計；針對噪聲底污染、假佔用洪泛、事件橋接、邊界延伸、最大能量視窗劫持的正式攻擊模組與對應防禦評估；把偵測、分段、防禦與分類一併納入最佳化目標的完整管線自適應攻擊；獨立雙 SDR 纜線注入與屏蔽環境下的實體驗證；事件層級的信心判斷與棄權機制；具備防竄改性質的證據保存機制；以及寬頻 channelizer、解調、解碼與協定解析等尚未觸及的功能範圍。

這些缺口大致分成兩條可以並行推進的路線，彼此不互相依賴先後順序。

**A. 數位完整管線攻擊**：在現有離線環境中，把攻擊面從單純的 AMC 輸入片段擴大到整個偵測與防禦流程，依序涵蓋噪聲底污染、最大能量視窗劫持、邊界延伸、事件橋接、假佔用洪泛，最後整合為針對完整管線（偵測、分段、防禦、分類一併納入最佳化目標）的防禦感知自適應攻擊。這條路線不需要額外的硬體，可以直接在既有的正式流程上擴充。

**B. 實體驗證準備**：與數位攻擊路線平行進行的是把系統本身補齊到可以承接實體驗證的程度，包括用真實 SDR 擷取的檔案完成 cfile 讀取器的外部有效性驗證、加入 rolling buffer 與跨處理批次的偵測器狀態保存以支援串流輸入、規劃獨立雙 SDR 的纜線注入實驗，最後進入屏蔽環境下的 OTA 驗證。

兩條路線不是先做完 A 才能開始 B，也不是必須先完成纜線與屏蔽驗證才能推進數位攻擊——數位環境下的攻擊面擴充與實體驗證平台的建置可以同時進行，最終目的是讓路線 A 建立的攻擊方法，在路線 B 準備好實體驗證能力時，能夠直接用於檢驗數位結果是否延續到有實體通道的情境。
